# API notes

The browser UI is the primary interface. An optional bearer token is also generated by the installer so a trusted local tool such as the `shincabinet.com` Site Manager can be integrated later.

Keep the token only in local configuration such as `/etc/shincabinet-image-manager.env` or a desktop-local secret file. **Never commit it to either Git repository.**

Example authenticated request:

```bash
curl \
  -H "Authorization: Bearer YOUR_TOKEN" \
  "https://manage-images.shincabinet.com/api/list?path=gallery"
```

Relevant endpoints:

```text
GET    /api/config
GET    /api/list?path=gallery
POST   /api/folders
POST   /api/upload
POST   /api/move
DELETE /api/item
```

When bearer authentication is used, CSRF headers are not required. Browser-session writes require the CSRF token supplied by the UI.

## Future Site Manager integration

A future image picker in Site Manager can:

1. Request `/api/list` to browse remote folders.
2. Display each item's `thumbnailUrl`.
3. Store the returned `url` field in the website's gallery/character/adoptable metadata.
4. Optionally upload via `/api/upload` without ever placing the file into the website repository.

That would turn the current manual **Copy URL** workflow into a direct remote-image chooser without changing where images are stored.
